## 并行规则

- 每台机器每次启动 **2 个 eval**（2 个端口），**两个 ckpt 必须不同实验**，避免同 ckpt 争抢
- M1: 6695=ft16, 6696=ft32(或cont.ft32)
- M2: 6694=ft0, 6695=ft64(或cont.ft32)
- 当前任务跑完后，从优先级列表找下一个自己负责的未启动任务

## 防干涉机制

| 层 | 位置 | 说明 |
|:--:|:----|:-----|
| ① 互斥门禁 | `nohup_eval.sh` 第27-49行 | 启动前检查结果目录：已完成→跳过，未完成→resume，目录存在无报告→拦截 |
| ② 硬检查门禁 | `nohup_eval.sh` 第73-84行 | server 启动后读 `/proc/PID/cmdline` 验证 ckpt 匹配 |
| ③ Resume检查 | `nohup_eval.sh` 第91-104行 | resume 时比对 eval_report.json 中的 ckpt_path |
| ④ 分工文档锁定 | 本文件 | 先在表中标记 `🔄Mx 端口`→再启动，防止两机器抢同一任务 |

**流程：** 读分工文档找到自己负责的 ⏳ 任务 → 把状态改为 `🔄Mx 端口` → 启动 eval（脚本自动执行①→②→③） → 完成后改 `✅SR%`

## 使用方式

1. 启动新任务前，先读此文件看 **当前运行中** 和 **全局优先级队列**
2. 找到自己机器的最高优 `⏳未启动` 任务
3. 启动后把状态改为 `🔄机器代号 端口号`，更新 **当前运行中** 表
4. 完成后把状态改为 `✅SR%`，从 **当前运行中** 移除
5. M1 负责维护文档结构，M2 只更新自己任务的进展状态
