## 执行摘要

移动操作（Mobile Manipulation）是具身智能从固定桌面任务走向真实家庭、仓储、实验室与公共服务场景的关键能力。与固定桌面操作不同，移动操作要求机器人在非结构化环境中完成目标搜索、导航接近、视角调整、遮挡恢复、可操作状态判断、拿取、移动、放置与失败恢复等长时序任务链。机器人在这一过程中会经历视角剧烈变化、目标部分或完全遮挡、导航与操作坐标系切换、可操作位姿不稳定、错误累积与恢复困难等问题。仅依赖当前观测、固定流程或局部反应式策略的系统，往往难以在长时序任务中稳定判断“下一步动作会使世界变成什么样”，也难以在早期发现并规避后续失败风险。

本项目研究对象是面向移动操作的 World Action Model（WAM）。在本文档中，WAM 指面向移动操作任务的未来状态、未来表征、未来可见结果或 action-relevant future 的建模、构建、接入与评测系统。WAM 的核心目标不是生成视觉上好看的未来视频，而是输出能够被下游决策、导航、操作或任务推进模块使用的未来信息。本项目不研究 VLA 本体，不研究 VLA backbone、action head、Flow Matching policy 或通用机器人基础模型训练，也不把 StarVLA、OpenVLA、π0、GR00T 或任何具体仓库作为立项阶段绑定底座。VLA、传统规划器、导航器、操作 primitive 或移动操作执行器可以作为 WAM 输出的下游使用方，但不是本项目研究对象。

本项目采用 P0/P1/P2 分阶段技术路线。P0 为 **Video-Generation-Free WAM**，不生成未来视频，不以重型视频生成模型为主干，而是构建轻量的 compact future representation 预测模型，并将其输出接入至少一个下游模块完成任务收益验证。P1 为 **Latent-Only WAM**，是三个月内必须推进的正式任务，研究 video-derived latent、world model hidden states、dynamics feature、denoising feature 或中间 latent future representation 是否能更好表达移动操作中的视角变化、目标接近、遮挡恢复、操作前状态变化和导航—操作衔接。P2 为 **Render-and-Decode / Video-generation WAM**，是后续扩展与局部验证方向，关注 rendered future、future keyframe、goal image、route video、visual subgoal 或生成式视频在移动操作中的适用性，但立项阶段不绑定具体实现框架、视频模型、benchmark 或工程路线。

项目周期为三个月。三个月内至少完成 P0 与 P1 的技术论证、原型验证和评测分析，形成一个可运行、可评测、具备 benchmark 竞争潜力的移动操作 WAM 原型。这里的“可运行原型”不是单纯离线模型，也不是只输出 loss 的实验脚本，而是包含可执行的 WAM 推理流程、可被至少一个下游模块使用的输出接口、可在仿真环境、benchmark、诊断任务或受控任务链中完成任务收益验证，并可记录 WAM-specific metrics 与 downstream task metrics 的评测流程。项目最终交付包括立项书、技术调研报告输入、详细设计输入、P0/P1 原型路线、数据与评测规划、实验报告、风险分析与后续 P2 扩展建议。

## 第一章 项目背景

### 1.1 移动操作成为具身智能落地的重要方向

具身智能的核心目标，是让机器人能够在真实物理世界中感知、理解、决策并执行任务。固定桌面操作、单步抓取和短时序放置任务已经形成大量研究积累，但真实家庭和服务场景中的任务远不止“看到一个物体并抓取”。机器人需要在大范围空间中移动，主动寻找目标，理解环境结构，选择合适视角，接近目标物体，处理遮挡，在操作前判断目标是否可达、是否可抓、是否需要调整姿态，并在任务失败后进行恢复。移动操作正是连接导航、感知、语言理解、操作控制和任务规划的综合能力。

家庭场景是移动操作的典型应用场景。机器人可能需要执行“去厨房找到杯子并放到餐桌上”“把遥控器从沙发旁拿到茶几上”“找到抽屉里的物体并放回指定位置”等任务。这些任务都不是单个动作能够完成的，而是由找物、接近、视角调整、拿取、转移和放置等多个阶段组成。相比工业结构化场景，家庭环境的物体摆放更随机，遮挡更多，光照更复杂，通道更狭窄，目标位置也更不稳定。因此，移动操作是检验机器人是否真正具备开放环境执行能力的重要方向。

### 1.2 长时序 household mobile manipulation 的任务特点

本项目聚焦 long-horizon household mobile manipulation。该类任务具有长时序、多阶段、强耦合和高不确定性四个特点。

第一，任务链路长。机器人需要从全局任务目标出发，连续完成目标搜索、导航接近、视角调整、可操作状态判断、抓取、搬运和放置。每个阶段的执行结果都会影响后续阶段。例如，导航阶段选择的接近角度会影响抓取时的可见性与可达性，抓取阶段的姿态误差会影响移动过程中的物体稳定性，放置阶段的目标表面状态会影响最终成功率。

第二，视角变化频繁。移动机器人在接近目标过程中，相机的位姿持续变化。远处看到的目标物体，近处可能因视角变化而被桌沿、家具或自身机械臂遮挡。固定桌面操作通常假设相机相对稳定，而移动操作必须主动处理相机视角带来的观测漂移。

第三，导航与操作耦合。导航不是单纯把机器人移动到目标附近，操作也不是单纯在固定位置执行抓取。机器人需要选择一个既能导航到达、又利于机械臂展开、同时能观察目标和执行操作的位姿。这种“导航—操作衔接”是移动操作区别于单纯导航或桌面操作的关键。

第四，失败恢复重要。长时序任务中，早期小错误可能在后续累积成任务失败。目标搜索失败、接近角度不佳、抓取姿态不稳定、放置区域判断错误，都可能导致系统需要重新观察、重新接近或重新执行。缺乏未来建模的系统通常只能在失败发生后被动重试，而难以及时预判风险。

### 1.3 当前移动操作系统对未来状态建模的不足

当前移动操作系统大致可以分为三类：固定流程式系统、反应式策略系统和端到端 VLA 系统。固定流程式系统通常将任务拆成观察、导航、操作、恢复等阶段，再通过人工规则或高层状态机串联起来。这类系统易于解释，但对环境变化和任务多样性的适应性有限。反应式策略系统直接根据当前观测输出下一步动作，适合短时序和局部控制，但面对长时序任务时缺少对未来状态演化的显式判断。端到端 VLA 系统具备较强的视觉语言理解和动作泛化能力，但其核心仍通常是从当前观测与语言指令映射到动作，未来状态建模往往隐含在模型参数中，难以单独检查、诊断和接入。

这些系统的共同不足是没有把“未来状态建模”作为一等公民。移动操作中的关键问题并不是“当前看到了什么”，而是“执行当前动作之后是否会更接近目标”“下一视角是否能看到目标”“接近后是否可操作”“操作后是否会产生新的失败风险”。如果系统缺乏对这些 action-relevant future 的建模，就只能通过更多试错来弥补，导致效率降低、失败率上升、恢复成本增加。

### 1.4 World Action Model 的研究价值

World Action Model 的价值在于把未来预测变成动作决策可使用的信息。WAM 不应被理解为单纯的视频生成模型，也不应被理解为普通 world model 的改名。普通 world model 可以预测环境状态如何变化，但 WAM 更强调预测结果必须 action-facing，即能够进入动作选择、动作验证、策略条件化或失败恢复链路。对于移动操作而言，WAM 的输出可以是未来目标可见性、未来可操作状态、未来 affordance、未来导航—操作衔接状态、未来失败风险或未来关键帧。这些输出都不必是完整视频，却必须对下游任务有用。

WAM 可以弥补当前移动操作系统的三个缺口。第一，它可以在目标搜索与视角调整阶段提供前瞻性判断，减少无效探索。第二，它可以在导航结束、操作开始之前判断当前状态是否已经具备操作条件，降低盲目操作率。第三，它可以在失败恢复阶段提供“下一步应该重新观察、重新导航还是重新操作”的依据。通过这些能力，WAM 能够帮助系统从被动反应转向预测式控制。

### 1.5 本项目与前序 VLA 项目的关系

前序 VLA 项目主要研究视觉、语言和机器人状态如何生成动作，其核心问题是 action policy 的构建、训练和泛化。本项目不重复研究 VLA，也不优化 VLA 的 backbone、动作头或训练 recipe。本项目研究的是 WAM，即未来信息如何被建模、如何被下游消费、如何在移动操作任务中形成收益。

两者可以形成上下游互补关系。前序 VLA 项目提供动作执行能力，本项目提供 future model / world prediction。后续系统集成阶段，WAM 的输出可以作为 VLA、导航器、操作 primitive 或传统规划器的输入、条件、评分项或校验信号。但在本立项书阶段，项目二的研究对象始终是 WAM 本体及其接入与评测闭环。

## 第二章 项目定位

### 2.1 项目研究对象

本项目研究对象是面向移动操作的 World Action Model。具体而言，本项目关注在移动操作任务中，如何定义、预测并使用 action-relevant future；如何设计不依赖视频生成的轻量未来表征；如何利用 latent-only 表征增强对动态场景、遮挡和视角变化的表达；如何评估 rendered future 或未来关键帧在后续阶段的适用性；以及如何将 WAM 输出接入下游策略、规划器、导航器、操作 primitive 或执行器中形成任务收益。

本项目的核心不是提出一个新的 VLA，也不是训练一个新的通用机器人基础模型，而是构建一个可以作为移动操作系统“未来预测层”的 WAM 模块。该模块应具备独立输入输出、独立评测指标和可替换的下游接口，使其能够服务多种执行系统。

### 2.2 项目核心问题

本项目需要回答五个核心问题。

第一，移动操作中的 future 应该预测什么？完整未来视频成本高、延迟大，且未必对任务有用。本项目需要识别对移动操作真正关键的 future representation，例如目标未来可见性、未来可操作状态、未来 affordance、navigation-to-manipulation representation、failure-risk representation 等。

第二，Video-Generation-Free WAM 如何做到可运行而不是停留在离线预测？P0 必须输出能被下游模块使用的 future representation，并通过任务收益验证其价值。

第三，Latent-Only WAM 相比 Video-Generation-Free WAM 是否具备更强的动态表达能力？P1 必须在相同或可比任务链上与 P0 对比，分析其在视角变化、遮挡恢复、导航—操作衔接中的优势与代价。

第四，Render-and-Decode / Video-generation WAM 在移动操作中的适用边界是什么？P2 不作为三个月主线，但需要为后续研究明确潜在价值、风险和局部验证方式。

第五，如何建立 WAM-specific metrics 与 downstream task metrics 的关联？如果 WAM 预测质量提高，却不能转化为任务收益，则该 WAM 不能被视为成功的 World Action Model。本项目必须设计从预测质量到任务收益的评测闭环。

### 2.3 与 VLA、普通 world model、视频生成模型的区别

本项目与 VLA 的区别在于研究对象不同。VLA 研究从当前观测和语言指令到动作的映射，输出通常是动作或动作 chunk；WAM 研究从当前观测、任务上下文和候选动作条件到未来信息的预测，输出是对下游有用的 future representation、latent future 或 rendered future。VLA 可作为 WAM 的下游使用方，但不是本项目研究对象。

本项目与普通 world model 的区别在于评价标准不同。普通 world model 可以追求状态转移预测或环境动态模拟，WAM 则强调未来预测必须 action-facing。一个预测得很准确但无法被下游策略使用的模型，不符合本项目对 WAM 的要求。WAM 的评测必须包括任务收益，而不仅是预测误差。

本项目与视频生成模型的区别在于目标不同。视频生成模型以视觉质量、时序一致性或图像逼真度为主要目标，而 WAM 以任务相关性、下游可用性和控制收益为核心。P2 可能研究视频生成或未来关键帧，但视频生成只是未来信息表达方式之一，不是项目目标本身。

### 2.4 项目技术边界

本项目明确不做以下内容：

1. 不研究 VLA 本体训练、VLA backbone 优化、action head 设计或 Flow Matching policy；
2. 不绑定 StarVLA、OpenVLA、π0、GR00T 或其他具体仓库作为立项阶段唯一底座；
3. 不以 DSWS + OBSERVE / NAVIGATE / MANIPULATE / RECOVER 四模式高层状态机作为主线；
4. 不在 P0 阶段生成未来视频；
5. 不在立项书阶段写死最终 benchmark、最终数据集或最终 P2 技术路线；
6. 不把固定桌面操作数据写成移动操作主证据；
7. 不把 LIBERO、RoboCasa、RoboTwin 等作为唯一主 benchmark；
8. 不展开代码目录、模型层数、batch size、训练命令、接口函数或 ROS topic 等详细设计内容。

这些边界确保本项目聚焦“面向移动操作的 WAM 构建与评测”，避免滑向 VLA 训练、视频生成、规则规划或工程适配项目。

### 2.5 P0/P1/P2 阶段定位

**P0：Video-Generation-Free WAM。** P0 是三个月内必须交付的主干。它不生成未来视频，不以重型视频生成模型为主干，而是预测 compact future representation，例如 future object-centric representation、future affordance、future manipulation-readiness、future navigation-to-manipulation representation、future action-conditioned state representation 等。P0 的关键验收不是离线 loss，而是 WAM 输出能否接入下游模块并产生任务收益。

**P1：Latent-Only WAM。** P1 是三个月内必须推进的正式任务，不是可选扩展。P1 研究 video-derived latent、world model hidden states、dynamics feature、denoising feature 或中间 latent future representation 是否能在移动操作场景中提供更强的未来表达能力。P1 不一定解码成可见视频，但必须与 P0 形成对比和任务收益分析。

**P2：Render-and-Decode / Video-generation WAM。** P2 是后续扩展与局部验证方向。P2 关注 rendered future、future keyframe、goal image、route video、visual subgoal 或生成式视频在移动操作中的适用性。立项阶段不绑定任何具体 P2 框架，也不承诺三个月内完整落地 P2 系统。

### 2.6 三个月项目目标

三个月内，本项目至少完成以下目标：完成面向移动操作的 WAM 技术论证和路线设计；完成 P0 Video-Generation-Free WAM 原型方案、输出定义、下游接入方式和任务收益验证；完成 P1 Latent-Only WAM 的原型设计或初步验证，并与 P0 进行对比；完成数据与 benchmark 筛选原则、三层数据体系规划和诊断评测指标设计；形成 P2 路线的技术调研输入和局部验证建议；输出可用于后续详细设计和实验执行的文档成果。

## 第三章 研究现状与问题分析

### 3.1 移动操作系统与 benchmark 现状

移动操作系统已经从早期的单一导航或桌面抓取逐步进入开放词汇、长时序、跨房间、真实机器人和高保真仿真的综合阶段。开放词汇移动操作任务强调机器人在未知环境中根据语言指令寻找物体并完成拾取放置；长时序家庭任务强调机器人在多阶段任务链中维持状态一致性和恢复能力；高保真仿真 benchmark 则试图在可重复环境中模拟真实家庭的视觉、物理和任务复杂度。

然而，从 WAM 的角度看，现有 benchmark 通常存在三个不足。第一，很多任务只报告最终成功率，缺少对未来状态预测质量的诊断指标。第二，很多数据集更适合训练策略或评估执行能力，而不是直接构造 action-conditioned future supervision。第三，固定桌面操作数据虽然成熟，但不能充分反映移动操作中的视角变化、导航—操作衔接、目标搜索和遮挡恢复。

因此，本项目在立项阶段不写死最终 benchmark，而是提出主 benchmark、训练数据和诊断评测集三层数据体系。具体选型将在技术调研报告和详细设计文档阶段确定。

### 3.2 WAM 技术路线现状

WAM 技术路线可以从生成内容和预测底座两个维度理解。根据生成内容，WAM 可分为 Render-and-Decode、Latent-Only 和 Video-Generation-Free 三类。Render-and-Decode 将预测推进到可见未来，如 future frame、goal image 或 route video；Latent-Only 停留在中间 latent、feature 或 hidden dynamics，不解码成图像；Video-Generation-Free 则不依赖视频生成模型，而直接预测语言 token、几何 primitive、affordance、路径、状态或 joint-embedding future。

从移动操作角度看，三类路线各有价值。Render-and-Decode 可解释性强，但成本高、延迟大，不适合作为三个月内完整主线；Latent-Only 表达能力强，可能捕获复杂动态，但隐变量可解释性和下游接入仍需验证；Video-Generation-Free 成本低、接口清晰，更适合三个月内快速构建可运行原型，但其表达能力和泛化能力需要通过 P1 对比验证。

### 3.3 Video-Generation-Free WAM 路线现状与不足

Video-Generation-Free WAM 强调不生成未来视频，而是直接预测任务相关 future representation。该路线的优势是轻量、低延迟、可解释、易接入下游执行器。在移动操作中，它可以预测目标未来可见性、未来可操作状态、未来 affordance、候选导航点价值、操作前准备度、失败风险等。这些信息可以被导航器、规划器、操作 primitive 或 VLA 使用。

其不足也很明显。第一，future representation 的设计容易依赖人工先验，不同任务之间缺少统一标准。第二，轻量表征可能不足以覆盖复杂视觉动态和长时序物理交互。第三，现有轻量预测方法往往停留在局部任务或离线预测，缺少系统性下游接入和任务收益验证。本项目的 P0 正是要将该路线从“轻量预测”推进到“可接入、可运行、可评测”的 WAM 原型。

### 3.4 Latent-Only WAM 路线现状与不足

Latent-Only WAM 使用 video-derived latent、world model hidden states、dynamics feature 或 denoising feature 等中间表征表达未来。该路线避免直接解码像素，又能利用视频世界模型或自监督模型学到的动态先验，理论上比 P0 的显式轻量表征更适合处理复杂遮挡、视角变化和多步动态。

其不足在于：隐变量通常不具备直接可解释性，如何判断 latent 是否包含对任务有用的信息仍需要诊断评测；latent 与下游模块之间的接口不天然清晰，如何压缩、选择或投影成策略可用信息仍需研究；计算成本通常高于 P0，三个月内必须控制范围，避免变成重型世界模型训练项目。因此 P1 的合理目标不是训练大型 latent world model，而是在 P0 的任务链和评测框架上进行可控对比。

### 3.5 Render-and-Decode / Video-generation WAM 路线现状与不足

Render-and-Decode / Video-generation WAM 生成 future frame、keyframe、goal image、route video 或 visual subgoal。这类输出对人类可解释性强，也可能在目标搜索、路线想象、关键视角选择等任务中发挥作用。但其主要问题是计算成本高、推理延迟大、视觉质量与 action-relevance 不一定一致。生成漂亮视频不等于能够提升移动操作成功率。

因此，本项目把 P2 作为后续扩展与局部验证方向。P2 在三个月内可以完成路线预研、适用场景分析或局部 demo，但不作为完整闭环主线。这样的阶段化安排可以避免项目过早被视频生成路线拖入高成本工程，同时保留未来扩展空间。

### 3.6 项目机会点

当前机会点可以概括为三点。第一，移动操作任务天然需要 action-relevant future，但现有系统对其建模不足。第二，WAM 三类路线已有清晰分层，但在移动操作场景下缺少统一的构建、接入与评测框架。第三，三个月周期内最可行的路线是以 P0 Video-Generation-Free WAM 快速建立可运行闭环，再以 P1 Latent-Only WAM 做能力增强与对比，P2 作为后续扩展。

本项目不是抽象讨论 WAM，而是构建可运行、可评测、具备 benchmark 竞争潜力的移动操作 WAM 原型。其核心机会在于把未来预测从“看起来合理”推进到“对下游任务有用”。

## 第四章 项目目标

### 4.1 总体目标

本项目总体目标是在三个月内完成面向移动操作的 World Action Model 技术论证、路线设计、P0/P1 原型验证和评测分析，形成一个可运行、可评测、具备 benchmark 竞争潜力的移动操作 WAM 原型。项目目标不是证明 WAM 这个概念是否成立，而是通过算法设计、实验闭环和工程实现，形成一个能够被下游模块消费并带来任务收益的 WAM 系统雏形。

### 4.2 P0：Video-Generation-Free WAM 可运行原型目标

P0 目标是构建不生成未来视频的 WAM 原型。它应接收移动操作任务中的当前观测、机器人状态、任务上下文和必要的候选动作条件，输出 compact future representation。该输出可以是未来目标可见性、未来可操作状态、未来 affordance、候选导航点价值、操作准备度、失败风险或其他任务相关未来信息。

P0 必须完成下游接入。至少需要选择一种下游使用方，如导航器、规划器、操作 primitive 或已有策略模块，使 WAM 输出能够影响任务执行流程。P0 还必须完成任务收益验证，对比使用 WAM 与不使用 WAM 时的任务表现，并记录 WAM-specific metrics 与 downstream task metrics。

### 4.3 P1：Latent-Only WAM 正式验证目标

P1 目标是在 P0 基础上引入 latent-only future representation，并与 P0 形成正式对比。P1 可利用视频世界模型、自监督模型或动态预测模型的中间特征，但不要求解码成可见视频。P1 的核心任务是判断 latent-only 表征是否在移动操作中的视角变化、遮挡恢复、目标接近、操作前状态变化和导航—操作衔接中提供更强能力。

P1 必须作为三个月内正式任务推进。其目标验收应包括：明确 latent 表征来源与输出形式；与 P0 在至少一个相同或可比任务链上完成对比；分析 P1 相比 P0 的任务收益、计算成本、鲁棒性和适用边界。

### 4.4 P2：Render-and-Decode / Video-generation WAM 扩展目标

P2 是后续扩展和局部验证方向。P2 目标不是三个月内完成完整视频生成闭环系统，而是在技术调研基础上评估 rendered future、future keyframe、goal image、route video、visual subgoal 或生成式视频在移动操作中的适用性。P2 可以在局部场景中验证可见未来是否有助于目标搜索、视角选择、导航—操作衔接或任务解释，但其具体实现方式、模型、数据和 benchmark 应在技术调研报告和详细设计文档阶段确定。

### 4.5 可运行原型定义

本项目中的可运行原型至少包含四项要素：

1. 可执行的 WAM 推理流程；
2. 可被至少一个下游模块使用的输出接口；
3. 可在仿真环境、benchmark、诊断任务或受控任务链中完成任务收益验证；
4. 可记录 WAM-specific metrics 与 downstream task metrics 的评测流程。

P0 可运行原型重点是非视频未来表征接入下游任务。P1 可运行原型重点是在 P0 对照基础上引入 latent-only future representation。P2 只要求局部验证，不要求三个月内形成完整闭环系统。

### 4.6 benchmark 竞争潜力目标

“具备 benchmark 竞争潜力”并不意味着立项阶段承诺具体榜单名次，而是指项目路线、数据规划、评测流程和原型结构具备与公开移动操作 benchmark 或主流代表工作进行对比的可能性。三个月内项目应完成候选 benchmark 调研、任务链对齐分析、评测指标设计和可比性判断。最终 benchmark 选型和具体指标阈值将在技术调研报告与详细设计文档阶段确定。

### 4.7 三个月交付目标

三个月内至少交付：正式立项书、技术调研报告输入、详细设计输入、P0 原型路线和初步实现、P0 下游接入验证、P1 原型或对比模块、P0/P1 对比分析、数据与 benchmark 筛选原则、风险与降级策略、项目总结报告。P2 只要求形成扩展路线预研或局部验证结论。

## 第五章 总体技术路线

### 5.1 面向移动操作的分阶段 WAM substrate 路线

本项目采用分阶段 WAM substrate 路线。P0 优先构建轻量、可解释、可接入的 Video-Generation-Free WAM；P1 在 P0 基础上引入更强的 latent-only future representation；P2 作为扩展方向研究 rendered future 或 video-generation future 的适用边界。三者不是互相替代，而是围绕移动操作任务需求形成成本、表达能力和可解释性的递进关系。

该路线符合三个月项目周期。P0 成本最低、最容易形成可运行闭环；P1 能够在 P0 基础上验证 latent 表征是否带来额外收益；P2 则保留未来扩展空间，但不消耗 P0/P1 的核心交付资源。

### 5.2 P0：Video-Generation-Free WAM

P0 的核心是预测 compact future representation。输入可以包括当前 RGB 观测、机器人状态、任务指令、历史短窗口观测、候选动作或候选子目标。输出不应是未来视频，而应是对下游有用的未来信息，例如目标未来可见性、未来可操作状态、未来 affordance、候选导航点价值、操作准备度或失败风险。

P0 的技术重点包括三个方面。第一，定义 future representation，使其既能被监督训练，又能被下游使用。第二，建立下游接入方式，使 WAM 输出能够影响导航、操作或任务切换。第三，设计任务收益验证流程，证明 WAM 输出不仅预测得“像”，而且对任务执行有帮助。

### 5.3 P1：Latent-Only WAM

P1 在 P0 的基础上研究 latent-only future representation。与 P0 相比，P1 的预测对象不再是完全显式或人工定义的 compact representation，而是 video-derived latent、hidden dynamics、denoising feature 或其他中间表征。P1 的优势在于可能捕捉更复杂的动态信息，尤其适合视角变化、遮挡恢复和长时序变化。

P1 的关键挑战是可解释性和接入性。因此，P1 不应只比较 latent prediction loss，而应在与 P0 相同或可比任务链中评估下游收益。P1 的输出可以通过投影、评分、条件化或检索方式转化为下游可用信号。详细的 latent 来源、模型结构和训练方式不在立项书阶段确定，应在详细设计文档中展开。

### 5.4 P2：Render-and-Decode / Video-generation WAM

P2 研究 visible future 的适用性。它可能输出 future frame、future keyframe、goal image、route video 或 visual subgoal。P2 的价值在于可解释性强，适合人类检查、任务可视化和关键阶段辅助决策。但 P2 成本高、延迟大，且视频质量与任务收益之间存在 gap。

因此，P2 在三个月内只做扩展与局部验证。它不绑定具体视频模型，不绑定具体 VLN 框架，也不作为核心验收项。P2 的合理目标是回答“哪些移动操作阶段值得生成可见未来，哪些阶段只需要 latent 或 compact representation”。

### 5.5 WAM 输出与下游策略 / 执行器接入

WAM 的价值必须通过下游接入体现。P0/P1 的输出可以以多种形式服务下游模块：作为导航目标点候选评分、作为操作触发条件、作为可操作状态判断、作为失败风险提示、作为策略输入条件，或作为多个候选子目标之间的排序依据。下游使用方可以是 VLA、规划器、导航器、操作 primitive 或执行器，但本项目不研究这些下游系统本体。

接入设计应保持抽象和可替换。立项书阶段只定义“WAM 输出必须能被下游消费”的原则，不写具体接口函数或通信 topic。具体接口形式将在详细设计文档中定义。

### 5.6 路线收敛机制与阶段切换原则

项目采用“P0 保底、P1 增强、P2 扩展”的收敛机制。若 P0 在任务收益验证中表现良好，则继续推进 P1 对比；若 P0 收益不明显，应优先分析 future representation 与下游接入是否合理，而不是立即转向视频生成。若 P1 成本过高，则保留 P1 的核心对比任务，缩小 latent 来源和任务范围。P2 始终作为可裁剪扩展，不影响 P0/P1 核心目标。

### 5.7 技术边界与不做内容

总体技术路线不包含 VLA 训练、Flow Matching action head 优化、DSWS 四模式状态机、完整视频世界模型训练、完整 3D 重建或真实机器人高风险闭环部署。立项书阶段不写死最终 benchmark、数据集、P2 具体路线或工程底座。

## 第六章 研究内容

### 6.1 移动操作中的 future representation 研究

本项目首先研究移动操作任务中哪些 future representation 值得建模。候选包括 future object-centric representation、future affordance、future manipulation-readiness、future visibility、future navigation-to-manipulation representation、future failure risk、future action-conditioned state representation 等。每种表示都需要回答两个问题：是否可从数据中构造监督或伪监督；是否能被下游模块消费并产生任务收益。

### 6.2 Video-Generation-Free WAM 构建与任务接入

P0 研究内容包括：定义轻量 future representation，构建不生成视频的预测模型，设计输入输出格式，确定监督信号来源，构建下游接入方式，并完成任务收益验证。P0 不能停留在离线预测，而必须将输出接入至少一个下游模块，形成闭环实验。

P0 的研究重点是“低成本可用”。它不要求预测完整未来，而是预测控制真正需要的未来。若 P0 能够在目标搜索、接近、视角调整或操作触发等环节提供稳定收益，即可作为后续 P1/P2 的基线和对照。

### 6.3 Latent-Only WAM 构建与对比

P1 研究内容包括：确定 latent-only 表征来源，构建未来 latent 预测或检索机制，设计将 latent 转化为下游可用信号的方法，并与 P0 进行任务级对比。P1 的评测不应只看 latent 重建质量，而应看 latent 是否在视角变化、遮挡恢复、目标接近和导航—操作衔接中提升任务表现。

P1 与 P0 的对比应尽量控制任务链、下游模块和评测指标一致，使差异主要来自 future substrate。这样才能判断 latent-only 路线是否值得后续投入。

### 6.4 Render-and-Decode / Video-generation WAM 路线预研

P2 研究内容包括：调研 visible future 的适用场景，分析 future keyframe、goal image、route video、visual subgoal 对移动操作的潜在价值，选择局部任务做可行性验证，并评估计算成本、延迟和可解释性。P2 不作为三个月内完整系统目标，而是为后续扩展提供依据。

### 6.5 WAM 预测质量与移动操作任务收益关联分析

本项目需要建立 WAM-specific metrics 与 downstream task metrics 之间的关联。WAM-specific metrics 可以包括目标未来可见性预测准确率、可操作状态预测准确率、失败风险排序质量、未来 affordance 一致性、latent dynamics 稳定性等。Downstream task metrics 可以包括任务成功率、阶段成功率、完成时间、路径效率、重试次数、失败恢复成功率等。

只有当 WAM-specific metrics 的提升能够解释或带来 downstream task metrics 的提升时，WAM 才真正完成了 action-facing future 的任务。

### 6.6 面向 benchmark 的评测闭环研究

本项目将建立面向 benchmark 的评测闭环，但不在立项阶段写死最终 benchmark。评测闭环需要包括：主 benchmark 或任务链、训练数据、诊断评测集、对照组、WAM-specific metrics、downstream task metrics 和失败案例分析。诊断评测集尤其重要，因为它能帮助区分 WAM 在遮挡、视角变化、导航—操作衔接等具体环节中的作用，而不只看最终成功率。

## 第七章 数据与评测规划

### 7.1 数据与 benchmark 选择原则

立项阶段只定义数据与 benchmark 的选择原则，不确定最终选型。候选 benchmark 应优先满足以下条件：覆盖移动操作任务链；包含长时序 household task；具备较好的 RGB 真实感或真实机器人数据；支持任务阶段分析；可构造 future representation 监督；具备公开 split、baseline 或可复现流程；三个月内工程成本可控。

### 7.2 主 benchmark、训练数据与诊断评测集三层体系

本项目采用三层数据体系。主 benchmark 用于核心移动操作任务评测，承担项目对外可比性。训练数据用于 WAM 训练或表征学习，可以来自仿真轨迹、真实机器人数据、视频数据或已有任务日志。诊断评测集用于分析 WAM-specific metrics，特别是目标可见性、可操作状态、视角变化、遮挡恢复、导航—操作衔接和失败风险等能力。

三层体系的意义在于避免用单一数据集承担所有任务。一个数据集可能适合训练但不适合评测，也可能适合 benchmark 但不适合构造监督信号。最终选型将在技术调研报告和详细设计文档阶段确定。

### 7.3 移动操作任务链对数据的要求

数据应尽量覆盖找物、目标接近、视角调整、遮挡恢复、拿取、移动、放置和失败恢复。数据中最好包含连续视觉观测、机器人状态、任务指令、动作或子目标、物体状态变化和任务阶段标注。若真实数据难以满足全部要求，可使用高保真仿真作为补充，但低保真 RGB 数据不应作为主 benchmark 证据。

### 7.4 RGB 真实感与场景复杂度要求

移动操作 WAM 依赖视觉和空间状态，RGB 真实感会直接影响视角变化、遮挡、目标识别和 future representation 学习。候选数据和环境应优先选择真实机器人 RGB 或 photorealistic / high-fidelity rendering。低质量渲染可用于快速调试、接口验证或辅助消融，但不能作为主要评测证据。

### 7.5 P0/P1/P2 对数据的不同需求

P0 需要能够构造 compact future representation 监督的数据，例如未来可见性、可操作状态、目标相对位姿、导航候选点收益等。P1 需要具备连续视觉或可提取 latent dynamics 的数据，便于构造 video-derived latent 或 hidden dynamics。P2 需要更高质量的视觉序列或可生成可见未来的数据环境，但 P2 在三个月内只做局部验证，不要求大规模训练数据。

### 7.6 评测指标规划

评测指标分为两类。WAM-specific metrics 用于评估预测质量，例如未来可见性准确率、可操作状态预测准确率、失败风险排序一致性、future affordance 稳定性、latent dynamics 一致性等。Downstream task metrics 用于评估任务收益，例如任务成功率、阶段成功率、完成时间、路径长度、重试次数、恢复成功率等。项目需要分析两类指标之间的关系，避免只优化离线预测而忽略任务收益。

### 7.7 技术调研阶段待确定事项

技术调研报告阶段需要确定候选 benchmark 排序、候选训练数据可用性、诊断评测集构造方式、P2 路线候选、下游接入对象和可复现成本。立项书阶段不做最终判断，只保留原则与接口。

## 第八章 实验规划

### 8.1 P0 Video-Generation-Free WAM 原型实验

P0 实验目标是验证轻量 future representation 是否能形成可运行闭环。实验应包含 WAM 推理流程、输出接口、下游接入和任务收益对比。对照组为不使用 WAM 的下游策略或固定流程，实验组为使用 P0 WAM 输出的系统。评测重点不是离线 loss，而是任务收益与失败类型变化。

### 8.2 P0 下游任务收益验证

P0 至少应接入一个下游模块，例如导航器、规划器、操作 primitive 或已有策略模块。验证任务可以从子任务开始，如找物—接近、接近—操作准备、拿取—放置，再逐步扩展到完整任务链。实验需记录 WAM-specific metrics 和 downstream task metrics，并分析 WAM 输出在哪些阶段发挥作用。

### 8.3 P1 Latent-Only WAM 对比实验

P1 实验应在 P0 已建立的任务链和评测流程上进行。核心对比是 Latent-Only WAM 与 Video-Generation-Free WAM 在相同或可比任务中的表现差异。实验应关注视角变化、遮挡恢复、目标接近和导航—操作衔接等场景。若 P1 计算成本明显高于 P0，则应同时记录成本收益比。

### 8.4 遮挡、视角变化和长时序鲁棒性实验

移动操作特有挑战必须通过专项实验体现。遮挡实验用于评估目标被部分或完全遮挡时，WAM 是否能预测更合适的观察或接近方式。视角变化实验用于评估机器人移动导致观察变化时，WAM 是否能维持目标与可操作状态的一致性。长时序鲁棒性实验用于评估多阶段执行中错误是否被提前发现或恢复。

### 8.5 household task 找物—拿取—移动—放置任务链实验

完整任务链实验用于评估系统级收益。任务链可以包含“找到目标物体—接近目标—判断可操作状态—拿取—移动到指定位置—放置”。该实验不要求一开始覆盖所有复杂家庭场景，但需要体现移动操作的长时序和导航—操作耦合特征。P0/P1 至少应在其中部分链路或简化完整链路上形成对比结果。

### 8.6 P2 Render-and-Decode / Video-generation WAM 局部验证

P2 局部验证可选择一个关键阶段，如目标接近、视角选择或 visual subgoal 生成，分析 visible future 是否对决策有帮助。P2 不要求完整闭环系统，也不作为核心验收项。若 P2 成本过高或效果不稳定，可退化为技术调研和定性分析。

### 8.7 benchmark 对齐与可比性分析

实验规划应保留与公开 benchmark 对齐的可能性。对齐内容包括任务定义、输入输出、评测指标、baseline 和可复现流程。若三个月内无法完成公开 benchmark 提交，也应形成可比性分析，说明后续如何进入 benchmark 竞争。

### 8.8 实验失败后的降级策略

若 P0 下游收益不明显，应优先诊断 future representation 是否选错、下游接入是否过弱、任务是否过难，而不是立即切换到 P2。若 P1 成本过高，应缩小 latent 来源和任务范围，只保留关键对比。若 P2 不成熟，应保留调研结论并退出主线。

## 第九章 创新点

### 9.1 面向移动操作的分阶段 WAM 构建路线

本项目提出面向移动操作的 P0/P1/P2 分阶段 WAM 构建路线。该路线不是简单把已有 world model 放到机器人任务中，而是根据移动操作对成本、延迟、表达能力和可解释性的不同要求，依次推进 Video-Generation-Free、Latent-Only 和 Render-and-Decode / Video-generation 三类 WAM substrate。

### 9.2 可接入下游执行器的 Video-Generation-Free WAM

本项目强调 P0 不只是轻量预测模型，而是可接入下游执行器的 WAM。P0 输出必须能够被导航器、规划器、操作 primitive 或策略模块使用，并通过任务收益验证其实际价值。这使得 P0 从离线 future prediction 变成移动操作系统中的 action-facing future 模块。

### 9.3 Latent-Only WAM 与 Video-Generation-Free WAM 的任务级对比

本项目将在统一移动操作任务链上比较 P0 与 P1，而不是分别报告两类方法的离线指标。这种对比能够回答“更强的 latent future representation 是否值得额外成本”这一关键问题，并为后续扩展提供依据。

### 9.4 Render-and-Decode / Video-generation WAM 的阶段化扩展

本项目不盲目追求完整视频生成，而是将 P2 定位为阶段化扩展与局部验证。这样既保留了 visible future 在 visual subgoal、future keyframe 和 route video 中的潜力，也避免项目在三个月内被高成本视频生成路线拖偏。

### 9.5 WAM 预测质量、任务收益与 benchmark 竞争力的闭环评测

本项目创新性地将 WAM-specific metrics 与 downstream task metrics 放在同一评测闭环中。WAM 的预测质量必须通过任务收益检验，任务收益也必须能够回溯到具体 future representation 的作用。这种闭环评测有助于形成可复用的移动操作 WAM 评测方法。

## 第十三章 风险与应对

### 13.1 benchmark 与数据选择风险

风险在于候选 benchmark 不完全覆盖移动操作任务链，或工程复现成本过高。应对策略是采用三层数据体系，主 benchmark、训练数据和诊断评测集分工明确；若主 benchmark 复现困难，则先用受控任务链验证 P0/P1，再在后续阶段对齐公开 benchmark。

### 13.2 P0 任务收益不明显风险

P0 可能出现离线预测指标合理但任务收益不明显的情况。应对策略是诊断 future representation、下游接入和任务难度三个环节；优先调整表征和接入方式，而不是立即放弃 P0 或转向视频生成。

### 13.3 P1 计算成本与接入复杂度风险

P1 可能因 latent 来源复杂、表征维度高或接入困难导致成本过高。应对策略是限制 P1 范围，只在 P0 已验证的任务链上做对比；优先选择可复用的 latent 表征；必要时缩小任务规模或只保留关键诊断场景。

### 13.4 下游策略 / 执行器接入风险

WAM 输出可能难以被下游模块有效消费。应对策略是在 P0 早期就定义清晰的输出语义，例如候选点评分、可操作状态、失败风险或触发信号；优先选择接口简单的下游模块进行验证。

### 13.5 长时序移动操作工程复杂性风险

完整 household task 链可能在三个月内过于复杂。应对策略是先验证关键子链路，如找物—接近、接近—操作准备、拿取—放置，再逐步组合成完整链路。验收标准允许以简化任务链作为目标验收的一部分。

### 13.6 P2 Render-and-Decode / Video-generation 不确定性风险

P2 的视频生成成本和质量不确定。应对策略是将 P2 控制为扩展和局部验证，不列为三个月完整主线。若 P2 技术不成熟，则输出调研报告和后续路线建议即可。

### 13.7 范围收敛与降级策略

项目采用 P0 保底、P1 增强、P2 可裁剪的策略。若时间或资源不足，优先确保 P0 下游接入和任务收益验证，其次完成 P1 对比，最后再考虑 P2 局部验证。任何阶段都不得通过扩大承诺来掩盖核心目标未完成。

## 第十四章 验收标准

### 14.1 最低验收标准

最低验收包括：完成正式立项书和技术调研报告；明确 P0/P1/P2 阶段路线；完成候选 benchmark 与数据源调研；完成 P0 Video-Generation-Free WAM 的方案设计和最小可运行原型；完成至少一个下游接入方案；定义 WAM-specific metrics 与 downstream task metrics；形成 P2 路线预研结论。

### 14.2 目标验收标准

目标验收包括：完成 P0 可运行原型并在至少一个移动操作子任务或简化任务链中完成任务收益验证；完成 P1 Latent-Only WAM 原型或对比模块；完成 P0/P1 在相同或可比任务下的对比分析；完成遮挡、视角变化或导航—操作衔接诊断实验；输出实验报告、失败案例分析和成本收益分析。

### 14.3 超预期验收标准

超预期验收包括：在完整 household task 链上验证 P0 或 P1 任务收益；完成与公开 benchmark 主流方法的可比结果；完成 P2 Render-and-Decode / Video-generation WAM 局部 demo；形成可展示的移动操作 WAM 系统演示；产出可用于论文雏形或技术汇报的系统结果。

### 14.4 文档验收标准

文档验收包括立项书、技术调研报告、详细设计输入、实验报告和项目总结。文档必须保持 WAM 项目定位，不得漂移到 VLA 训练、具体仓库适配或视频生成主线。

### 14.5 原型验收标准

原型验收要求包含可执行 WAM 推理流程、下游可消费输出、任务收益验证流程和评测记录。P0 必须满足可运行原型定义；P1 必须与 P0 形成对比；P2 不要求完整闭环系统。

### 14.6 实验与评测验收标准

实验验收要求同时包含 WAM-specific metrics 与 downstream task metrics。仅有离线 loss 不构成验收。任务收益可以通过阶段成功率、任务成功率、完成时间、路径效率、重试次数、失败恢复成功率等指标体现。具体阈值在详细设计阶段确定。

## 第十五章 结论

移动操作的核心难点不只是“看见物体并执行动作”，而是在长时序任务中持续判断行动会如何改变未来状态，并将这种判断用于导航、操作和恢复。本项目以 World Action Model 为核心研究对象，专门研究 action-relevant future 的建模、接入与评测，不研究 VLA 本体，不绑定具体工程底座，不把视频生成作为近期主线。

项目采用 P0 Video-Generation-Free WAM、P1 Latent-Only WAM、P2 Render-and-Decode / Video-generation WAM 的分阶段路线。三个月内至少完成 P0/P1 的原型验证和评测分析，形成可运行、可评测、具备 benchmark 竞争潜力的移动操作 WAM 原型。该项目既能为后续技术调研和详细设计提供清晰输入，也能为移动操作系统从反应式执行走向预测式执行提供关键基础。
